Briefing

Alliance roster

Guaranteed players always get a spot when they apply (unless banned for a no-show). Bans are automatic and per mode: a no-show blocks selection in that game mode only (Desert or Canyon) for 3 weeks (21 days) from the event date. If a player changes their in-game name, use ✏️ to rename them — all history, bans and fairness priority stay attached, and applications under the old name still match automatically. If the same person ended up as two roster entries (typo, different spelling), use 🔗 to merge the duplicate into the real one — histories are combined and the duplicate name becomes an alias.

Events

After each battle, open the event and mark no-shows. Each no-show gets the default 3-week ban, but you can set any length per player — 0 days = excused, still logged as a no-show but no ban. Add a note (reason, warning given, etc.) against anyone; notes show as 🗒 in the history grid. Bans apply only to the mode the no-show happened in. Deleting an event removes all its effects.

Settings

How selection works

1. Banned players (no-show within the ban window for this mode) are removed from the pool. Desert Storm and Canyon Storm bans are tracked separately — a no-show in one doesn't block the other.
2. Guaranteed applicants fill spots first. If more guaranteed players apply than there are spots, the least-recently-picked among them win.
3. Remaining spots go to non-guaranteed applicants ordered by longest time since last selection in that mode. Never-selected players come first. Ties are broken randomly.
4. Noon-only players go to the Noon team, evening-only to Evening, and "both" players fill whichever team has more space — availability never changes your odds of getting in.
5. Within each team, starters are chosen by: guaranteed players first, then longest time since last STARTED in that mode (never-started first, ties random). The rest are substitutes. You can toggle roles before saving.
6. Unselected applicants form a ranked waitlist for drop-out replacements.

Canyon Storm players

Combat attributes used by CS Build only: Power, T1 type (Tank / Missile / Aircraft) and Player type (Roamer / Holder / Flex). This is separate from the main Roster tab, which decides who plays; this decides where they stand. Records are matched to the roster by name, so renaming or merging someone on the Roster tab carries their CS data across automatically. Power drives everything — the snake draft and the sub pairing both use it, so anyone left at 0 will land badly.

CSV columns: name, power, t1, playertype — the last two are optional and default to Tank / Holder.

Storm Build

Reads a saved event and takes its picked players and their starter/sub roles exactly as the fairness selection set them — this tab never changes who plays. It then places them into groups by power and T1 spread, pairs each sub to a starter, and generates the mail and poster.
For Canyon Storm the two slots run as Team A (noon) and Team B (evening). For Desert Storm they stay as the Noon and Evening squads.

Briefing

"Log sub pairings" records who received a sub this week, so that sub duty rotates fairly the next time two players are tied on power. It doesn't lock or change the event.

Storm squad setup

How many starters and subs each group takes, per game mode. Setting a group's subs equal to its starters gives every starter their own dedicated sub; setting subs to 0 means that group runs without cover. The totals want to match the picked squad (e.g. 20 starters / 10 subs).
Kind drives placement: power takes the strongest non-Roamers, mid groups are snake-drafted by power and balanced for T1 spread, and roam takes your designated Roamers first. Have exactly one power and one roam group per setup.
